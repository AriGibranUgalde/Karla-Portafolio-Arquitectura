# Project Scope and Requirements

## Objective
Transform the existing university web project into a professional personal architecture portfolio.

## Remove
- Previous firm.
- Construction company.
- University project identity.
- Institutional branding.
- Previous services.
- Previous team information.
- Fictional clients.
- Academic test data.
- Projects that are not part of the personal portfolio.

Do not migrate institutional or company-related content automatically.

## Allowed Content
- Professional name.
- Biography.
- Professional photo.
- CV.
- Education.
- Professional experience.
- Skills.
- Software.
- Specialties.
- Professional contact information.
- Professional networks.
- Personal and professional architecture projects.
- Renders.
- Plans.
- Diagrams.
- Photographs.
- PDFs.
- Professional documents.

## Technical Expectations
The project must be:
- Maintainable.
- Responsive.
- Secure.
- Fast.
- Portable.
- Executable locally.
- Production-ready.
- Compatible with future OCI deployment.
- Easy to update through organized content files.

## Non-Goals
Do not build:
- CMS.
- Admin dashboard.
- User management.
- Authentication system.
- CRUD interface.
- Complex backend without a real need.
- Microservices.
- Kubernetes.
- Distributed systems.
- Multiple databases.
- Unnecessary cloud dependencies.
